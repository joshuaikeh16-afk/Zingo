# Permanent class Awakening — 2026-10-04

Implemented and deployed to linked Supabase project `skmlktywdmsbjyybtmhm`. Frontend files still need the existing Git push/hosting publication. No new API keys are required.

1. **Files:** new `js/awakening.js`, `battle-classes.js`, `battle-progress.js`, `battle-progress-model.js`; updated `js/social.js`, `js/inbox.js`, `css/product.css`; new Awakening/progression SQL, browser, live and model tests; updated existing battle fixtures.
2. **Migrations:** `20261015_battle_progression_records.sql` and `20261016_permanent_class_awakening.sql` are applied and recorded in migration history. Do not replay unrelated historical migrations; the repository still lacks a complete fresh-install baseline.
3. **Schema/functions:** `battle_classes`, `battle_identities`, private `awakening_questions` and `awakening_sessions`; `battle_stats.best_streak`; identity/progress/begin/answer/finalize/acknowledge RPCs; private scoring/view helpers and wrappers for existing profile/challenge functions.
4. **Security:** definitions, answers and score audits have no client SELECT grants. Authenticated users see only their own progression. Profile editing uses an explicit column allowlist; moderation, identifier and TRUNCATE access is closed. Battle-state rewards expose only the caller's award. Existing membership/acceptance authorization remains enforced.
5. **Questions:** version 1 has 24 main scenarios (12 combat, 12 everyday) and 20 pair-specific determinants. Each exam chooses six combat and six everyday scenarios, with stable answer IDs and a shuffled order frozen in its server snapshot. Answers affect several hidden traits rather than directly assigning one class.
6. **Scoring:** authenticated answer IDs are validated against the current server-stored question. Private trusted weights accumulate power, strategy, adaptability, defense and risk; authoritative class scoring runs in PostgreSQL. The browser receives neither weights nor probabilities.
7. **Ties:** close top scores add exactly two scenarios for that pair, capped at 14 total questions. Remaining ties resolve deterministically using secondary trait contributions, dominant traits and a stable final ordering. No random class assignment occurs.
8. **Permanence:** one identity per auth account, valid-class FK, immutable class/version/completion trigger, revoked direct mutations and serialized finalization. Repeat or racing requests cannot replace the first legitimate assignment. Assignment happens before the reveal; Accept destiny only acknowledges it. No selector, retake, reset or class-change UI exists.
9. **Resume:** answers and the frozen question snapshot persist server-side. Reopening resumes the next unanswered question. Expired sessions reject answers until resumed; resuming extends the same session without new questions. Confirmed answers cannot be changed, and identical retries do not count twice. Completed accounts receive their existing result, never another exam.
10. **Registry:** five original SVG emblems and centralized metadata cover Warrior, Wizard, Ninja, Guardian and Rogue. Server metadata separates attack, defense, motion and future ability definitions. Existing accounts are not assigned classes automatically.
11. **Reveals:** Warrior uses slash/impact/sparks; Wizard orbital glyph convergence; Ninja fast slash/afterimage; Guardian barrier formation/dispersal; Rogue visual misdirection and a sharp final reveal. Real class assignment is never faked. Effects use SVG/CSS and primarily transform/opacity, with reduced-motion treatment.
12. **Profiles:** public identity shows class and Unranked; no competitive league engine existed, so no fictional league is assigned. XP, level progress, wins/losses/draws, win rate and current/best streak appear only in the owner's UI. Best streak recovers available retained history and records future streaks; deleted historical results cannot be fully recovered.
13. **Integration:** explicit own battle-journey, challenge creation and invitation acceptance actions enter Awakening when needed. Server challenge/acceptance gates require the participant's identity. Viewing another profile or spectating a card does not start determination. Classes appear on challenge cards and battle participant presentation. Existing discussion/opinion mechanics remain intact.
14. **Responsive/accessibility:** Chrome checks passed for questions and reveals at mobile, landscape, tablet and desktop sizes, native keyboard radio navigation, touch target size, wrapping/scroll bounds, reload/resume, assigned-before-ack, five class visuals and reduced motion. Screenshots were visually reviewed; a conflicting global radio style was corrected and retested. Physical phone testing remains outstanding.
15. **Security tests:** deployed rollback fixtures passed for forged class arguments, invalid/foreign/duplicate/skipped decisions, incomplete/expired finalization, immutable identity, protected profile fields, public/private stats, bounded determinants, challenge gating and reward privacy. Live temporary-account requests passed for exact resume, protected REST writes, competing final decisions, parallel finalization, no repeat exam and public class/private XP. Test accounts were removed; final database audit confirmed zero temporary Awakening users. Existing chat/groups/media/onboarding/social/XP SQL regressions and focused Discussion browser checks passed.
16. **Checks:** six model/provider test files passed; static assets/imports/JS/Edge syntax, six Edge TypeScript semantic files and diff whitespace checks passed. There is no package build/lint pipeline. Remote Deno declarations remain outside the IDE semantic check. Browser fixtures validate presentation; live tests separately validate the deployed server.
17. **Deferred:** final class combat balance, abilities and competitive league rules remain deferred under the latest specification. Direct invitations are not yet a playable combat engine. Pets, companions, shops, inventory, currencies, rerolls and extra classes were not added.
